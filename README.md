# MiniMAX H3 Ref2VA/I2VA 视频质量优化器（Web 控制台版）

> 版本：**2.0正式版** · 协议：MIT · 联系：[微博 @快乐肥宅庆先森](https://weibo.com/u/2987585965)

一个**本地 Web 界面驱动**的 MiniMax-H3 视频质量优化器（通过迭代提示词提升画质/表现），支持两条流程：

- **Ref2VA**（参考图/视频 → 视频）：六段英文 full-reference 提示词，支持 A/B 两种参考模式；
- **I2VA**（首帧图生视频）：**1 张**参考图强制作为视频第一帧，按 MiniMax 官方 I2VA 规范直出**英文**提示词（首帧声明 + 三字段）。剧本仍为中文，仅台词/画面内文字按规范逐字保留原文。不吃参考音频；**快速渲染与 Ref2VA 同一套机制**。

它把提示词当作唯一变量，在固定模型/参数/种子下，通过 LLM 写剧本 → ComfyUI 渲染 → LLM 评分收敛，逐步把一条视频的提示词优化到更好画质/表现。

---

## 它做什么

```
写剧本(LLM) → 成稿提示词 → ComfyUI 渲染 → 抽帧/评分(LLM) → 依分数重写/演进
                    └──────────── 达标 / 迭代上限 / 刷不动 则出最终最优 ────────────┘
    成稿方式：两条流程均按官方规范写**英文** —— Ref2VA = 六段 full-reference；I2VA = 首帧声明 + 三字段
```

- **准入**：先拿到一条 ≥ 分数的合格基线；
- **爬山**：在基线上按“优化目标+薄弱点”逐个改进，只采纳更好的，退步换方向重试；
- **精渲**：可选用全质量工作流对最优提示词再渲一次最终产物。

## v2.0 更新

### 1. 单次生成长度上限 15 秒 → 60 秒
- MiniMAX H3的训练集只有15秒，时间长了会发生内容和画质漂移导致可用性大幅降低所以官方限制15秒输出，本次更新通过让更强的LLM模型来参与反馈校准的方式实测可以在60秒内保持相对较好的一致性（但不保证与15秒拥有完全相同的输出质量）。

### 2. 长视频提示词设计（>15 秒自动生效）
- **运动铺满全片**：强制校准长视频中的动态一致性
- **新内容均摊到每一拍**，避免模型在后段"绕回开头"。
- **光照与色彩的连续演变**，避免模型在未训练的超长视频生成调节下发生光照与色彩漂移
- **单镜连续**；若确需切换，切点所在拍同样要有运动。
- **声音连续性**（长片常见退化是后半段音频变弱）。
- **≤15 秒的提示词字节不变**（仅在 >15 秒时注入）。

### 3. 长视频检测方法
- **抽帧修复**：旧实现 `t = dur/n*i` 使最后一帧落在 `(n-1)/n` 处，**永远采不到最后 1/n 段**——而尾部正是退化最集中的区域。故采用均匀覆盖全片并**强制包含末帧**的方法。
- **抽帧数随时长自适应**：60 秒 → 40 帧（短片仍为 32 帧）。
- **新增 `core/video_metrics.py`**（纯标准库 + ffmpeg，**无需 numpy/PIL**）：逐秒采 32×32 灰度序列 + 首末彩色帧 + 首尾音频电平，按阈值判定并输出：尾部运动比、尾部冻结、近静止占比、对比度下滑、色调恒定、尾部音频变弱。
- **指标作为"地面真相"注入评审**：同时打印到日志，并附长视频评审规则，视觉 LLM 的判断不得与之矛盾。
- **复读相关降级为辅助证据**：该指标基线很高（静态机位/慢速演进的正常长镜头也会很高），而实测真实的"绕回开头"案例只有 0.588——阈值定高会**同时误报与漏报**，故必须与尾部运动衰减/对比度下滑同时出现才判定。

### 4. 前端与自检
- **环境自检**（页面「环境自检」按钮）：可以一键检测ComfyUI 状态、**模板所需节点**、所选模型/CLIP/LoRA 是否真实存在、所选模型的权重格式、ffmpeg、LLM 端点。
- **ComfyUI 状态灯**：页面常驻显示在线/离线与显存余量，30 秒自动刷新。
- **参考图持久化**：参考图/音频刷新页面自动恢复并显示缩略图。
### 性能优化
- **`weight_dtype` 可选**：`default / fp8_e4m3fn / fp8_e4m3fn_fast / fp8_e5m2`；选 GGUF 时自动忽略并提示。

## 低显存分块（可选，默认关闭）

把「刚好爆显存、跑不动」的档位救回来：在 Sage 注意力补丁之后，按需串入 ComfyUI-KJNodes 的两个节点，**只降采样期的临时激活，不改权重、帧数、采样器、latent、VAE 和分辨率**。

| `low_vram` | 插入的节点 | 说明 |
|---|---|---|
| `off`（默认） | 无 | 图与原来**逐字节一致** |
| `mlp` | `MiniMaxChunkFeedForward` | MLP(SwiGLU) 沿 packed token 维分块；int8 按 token 量化 → 数值精确 |
| `mlp_attn` | 上面那个 + `MiniMaxLowVRAMAttention` | 再把注意力按头分组（头之间独立 → 结果等价），并更早释放中间量；**会与 Sage 补丁组合**，保留它的 forward |

- 分块数在页面「高级 / 性能」里可调（`chunk_chunks` / `chunk_head_chunks`，默认 8 / 8）；packed token 短于 4096 时不切块。
- **实测边界（本机 RTX 5090 D v2 24 GB + 19.53 GB INT8 模型 + 2 步）**：
  - ✅ **救得回"刚好爆"的档**：30 秒 @0.8MP 原本不可用 → 开 `mlp_attn` 后 **301 秒完整出片**（1216×672 / 736 帧 / 30.67 秒）；
  - ❌ **救不回"超太多"的档**：60 秒 @0.6MP 即使 8+8 也会落到共享内存里 0% 卡死（比硬 OOM 更难收拾，要重启 ComfyUI）；
  - ⚠️ **它不改变峰值读数**：本机所有配置（含 5 秒 @0.3MP）峰值都是 23.8 GB，所以判断有没有用只能看"能不能跑完 + 多久"，别盯峰值。
- **⚠️ 它会改变输出位**：同 seed 下 `off` / `mlp` / `mlp_attn` 三组产物哈希两两不同（各自可复现）。所以**整轮优化期间必须保持同一设置**，不能中途开关——否则爬山比较分数就没意义了。
- 需要 KJNodes 提供这两个节点（老版本可能没有）；缺失时「环境自检」只会**告警**，不影响默认流程。详细实测见 `VERIFICATION.md`。

## 环境要求

- **Python 3.10+**（工作台只用标准库，无需第三方 pip 依赖；用系统 Python 即可）。
- **ComfyUI**：已装 MiniMax-H3 模型（UNET/CLIP/VAE）与所需自定义节点（`ComfyUI-MiniMax-H3-Turbo`、`ComfyUI-KJNodes`）。**本项目不内置、也不依赖任何特定 LoRA**：两条流程的工作流里都没有 LoRA 节点，加速 LoRA 一律由你在页面「LoRA」区自行加载，走的是 ComfyUI 自带的 `LoraLoaderModelOnly`，**不需要额外的 Custom Node、也不需要专用工作流**。加载后请把**采样步数设成与该 LoRA 匹配的值**（例如 8 步 turbo 类 LoRA 就把步数设为 8）——快速渲染只缩分辨率与步数，不会替你加载或识别 LoRA。目前实测过的例子是 `minimax_h3_ref2v_turbo_8step_v1.0_768p_comfyui_resized_avg_rank_64_bf16.safetensors`（可选，非必需）。
- **一个 OpenAI 兼容的 LLM 端点**（能看图/多模态，用于写剧本与评分；也可用云端 API）。
- **ffmpeg**：需位于 PATH 且名为 `ffmpeg.exe`（用于评分前抽帧/抽音频；缺失会明确报错并中止，而不是无限重写）。
- 参考音频分析需另配**音频 LLM**（可选）。

## 快速开始

1. 克隆仓库（**本仓库不提供发布 zip 包**，请用 git）：

   ```bash
   git clone https://github.com/klfzqxs/ref2va-h3-video-optimizer.git
   ```

   - 没装 git 的话，在仓库页点 **`Code → Download ZIP`** 下载 GitHub 自动生成的源码包，解压到任意目录即可。
   - 以后更新：在仓库目录里 `git pull`；想固定在某个发布版本：`git clone -b v2.0 https://github.com/klfzqxs/ref2va-h3-video-optimizer.git`（把 `v2.0` 换成你要固定的版本标签）。
2. 双击仓库里的 **`run.bat`**（自动选 Python、起服务、自动打开浏览器）。
   - 本机访问 `http://127.0.0.1:8090/`；局域网 `http://<本机IP>:8090/`。
   - 若找不到 `python`，在 `run.bat` 顶部加 `set "PYTHON=C:\你的Python\python.exe"`。
3. 页面上：
   - 填 **ComfyUI 地址** → 点「读取 ComfyUI 模型列表」→ 选好 **模型/CLIP/LoRA/采样器/调度器**；
   - 填 **LLM 地址/模型/API Key** →（可选）点「读取 LLM 模型列表」；
   - 在参考图区上方选 **流程**：**Ref2VA** 支持多图/参考音频与 A/B 模式；**I2VA** 只需 1 张首帧图（A/B 与参考音频会自动隐藏）；
   - 填**画面描述**、上传**参考图/音频**（可选，注明用途）；
   - 点「运行优化」/「任务排队」，页面看日志与结果视频。

## 配置字段（`config.json`，主要）

| 字段 | 说明 |
|------|------|
| `story`（必填） | 画面内容/剧情描述 |
| `flow` | 流程：`ref2va`（默认）或 `i2va`（首帧图生视频） |
| `optimize_target` | 本轮要重点达成的质量点 |
| `refs` / `audios` | 参考图/音频：`[{path, note}]` |
| `video_edit` | 是否 B 方式（自动用上一步视频作参考） |
| `llm_base` / `llm_model` / `llm_api_key` | 写剧/评分 LLM（必填地址+模型） |
| `audio_llm_base` / `audio_llm_model` / `audio_llm_api_key` | 音频 LLM（可选，做参考音频分析/音频评审） |
| `comfy_url` | ComfyUI 地址（默认 `http://127.0.0.1:8000`） |
| `model` / `clip` / `loras` | 模型名 / CLIP 名 / `[{name,strength}]`（ComfyUI 内全名，提交前自动规范化） |
| `weight_dtype` | UNET 权重精度：`default` / `fp8_e4m3fn` / `fp8_e4m3fn_fast` / `fp8_e5m2`（**仅 safetensors 生效**；GGUF 会被自动忽略并告警） |
| `ref_image_size` | 参考图尺寸策略（仅 Ref2VA）：`match`（按画幅缩放，默认）/ `max`（2048 短边，更准但更慢更吃显存） |
| `review_frames` | 评审抽帧数（默认 32；长视频 >15 秒自动抬到 40，**末帧一定采到**） |
| `low_vram` | 低显存分块（**可选，默认 `off`**）：`off` / `mlp` / `mlp_attn`；`chunk_chunks` / `chunk_head_chunks` 默认 8 / 8。**会改变输出位，整轮必须固定** |
| `sampler` / `scheduler` / `steps` | 采样器/调度器/步数；**两条流程均按此生效**（勾选快速渲染时步数自动 ×0.707） |
| `megapixels` / `aspect` | 分辨率 / 画幅 |
| `duration` | 时长（秒，**1–60**）。≤15 秒＝H3 训练范围；>15 秒自动走长视频分支。**超过 60 秒直接报错**（不做静默夹取）。实际提交帧数按 `17k+5` 网格向上吸附（60 秒 → 1450 帧 ≈ 60.4 秒） |
| `quick_render` / `fine_render` | 快速渲染（仅分辨率与步数 ×0.707，耗时约减半）/ 结束精渲（全分辨率全步数再渲一次） |
| `admission_threshold` / `max_iterations` / `base_patience` | 准入线 / 迭代上限 / 同基线耐心 |

> **快速渲染（`quick_render`）**：模型、采样器、时长、画幅、LoRA 与精渲**完全相同**，只把
> 分辨率（`megapixels`）与采样步数各乘 **0.707** 并向下取整（分辨率按 `ResolutionSelector` 的
> `step=0.1` 取整，步数取整到整数、下限 1）。因 0.707 × 0.707 = 0.5，渲染耗时约为精渲的一半，
> 提示词遵从度下降有限。该模式**不注入任何 LoRA**——要加速请在页面「LoRA」区自行加载。

## 长视频（15–60 秒）

单次生成长度上限是 **60 秒**。依据是本项目的实测（512²、8 步、RTX 5090 D v2 24 GB，全部**单次采样**——非拼接、非续写、非插帧）：

| 时长 | 帧数 | 端到端 | 对比度 | 色彩漂移 | 观感 |
|---|---|---|---|---|---|
| 15.08 s | 362 | 80 s | 62.5 | 24.2 | 训练范围上界，稳定 |
| 30.67 s | 736 | 180 s | 61.6 | 46.9 | 冷暖对比强、层次丰富 |
| **60.00 s** | **1440** | **483 s** | **74.8** | 17.0 | **质量高峰**（夜景峡谷→晨光草甸→湖泊→雪山→溪流） |
| 90.00 s | 2160 | 975 s | 30.0 | 3.0 | 明显降质：冷灰低饱和、光照恒定、音频弱 4 dB，且开头场景在后段重现 |

> 注：表中帧数是实测记录的名义值；按 H3 的 `17k+5` 帧网格，请求 60 秒时实际提交 **1450 帧 ≈ 60.4 秒**（页面日志会打印实际帧数）。

- 耗时近似**线性于 token 数**（15→90 秒：时长 ×5.97、耗时 ×12.2）；显存峰值随时长几乎不变（全程 23.0–23.6 GB / 24.4 GB，未 OOM）——瓶颈是常驻权重与激活，不是时长。
- 超过 15 秒时程序自动接管两件事：
  1. **提示词**（`system_director` / `system_i2va` 追加规则）：运动铺满全片、新内容均摊到每拍、光照色彩写成贯穿全程的连续演变、单镜连续、声音贯穿到最后一拍。实测同一模型同一长度下，**把事件集中在前半段会让尾部运动衰减一半以上**（尾/均 0.46 vs 恒定运动 0.55–0.94）。
  2. **检测**（`core/video_metrics.py` + 长视频评审规则）：评审抽帧数随时长自适应（60 秒→40 帧）并**强制包含末帧**；客观指标作为地面真相当作硬约束交给评审。**复读相关只作辅助证据**——该指标基线高（静态机位/慢速演进的正常长镜头也会很高），必须与尾部运动衰减/对比度下滑同时出现才判定为"绕回开头"。
- 想要更长且不降质：优先"**分段生成 + 用尾帧续接**"，而不是继续拉长单次（60–90 秒已是拐点）。
- 长视频里**步数比时长更值得投入**：20 步比 8 步细节明显更实（水花、岩石纹理、草叶边缘），而耗时只按步数线性增加（15 秒档 80 s → 140 s）。

## 常见问题

- **模型名报 `not in list`**：在页面用「读取 ComfyUI 模型列表」选真实名即可（提交前会自动规范化，含子目录）。
- **`value_not_in_list` 采样器/调度器**：用下拉/候选输入框选 ComfyUI 里的值。
- **`[warn] 未找到 ffmpeg` → 无限重写/无评分**：装 ffmpeg 并确认名为 `ffmpeg.exe` 且在 PATH；缺失会直接报错并中止（已加固）。
- **参考音频分析**：需配置音频 LLM，并给参考音频注明“参考什么”。
- **B 方式**：显存占用更高，依赖本机 ComfyUI 在线。
- **I2VA 提示「必须提供 1 张参考图」**：I2VA 流程必须上传 1 张图，它会**强制作为视频第一帧**（多余参考图会被忽略）。
- **I2VA 下「模式 A/B」「参考音频」不见了**：属正常——I2V 工作流只吃首帧图、不吃参考音频。（**快速渲染两条流程都可用**。）
- **I2VA 渲染报节点缺失**：需 ComfyUI 装有 `MiniMaxH3ImageToVideo` / `MiniMaxH3SigmaShift` / `ResolutionSelector` / `ComfyMathExpression` 等节点，以及 `ComfyUI-KJNodes` 提供的 **`PathchSageAttentionKJ`**（`sage_attention=sageattn3`）与 **`MiniMaxH3MemoryEfficientSageAttentionPatch`**（两者与 Ref2VA 相同，需 sageattention 3）。I2V 用的 UNET/VAE/CLIP 需自行准备。
- **加速 LoRA**：两条流程的工作流都**不含任何内置 LoRA**，快速渲染也只是缩分辨率与步数、不会替你加载 LoRA。需要加速（lightx2v / 8 步 turbo 类）时，在页面「LoRA」区自行添加（可用「读取 ComfyUI 模型列表」列出），并把步数设成与该 LoRA 匹配的值。
